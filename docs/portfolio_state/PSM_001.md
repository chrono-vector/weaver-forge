# PSM-001 — Portfolio State Metadata v0

PSM-v0 is a closed, non-authoritative metadata format for describing accepted
portfolio state by reference to existing authoritative records. It does not
create accepted state and is not a runtime subsystem, transition engine,
promotion engine, authority registry, production gate, or evidence authority.

## Record profile

The top-level fields are `schema_version`, `portfolio_state_id`,
`subject_scope_id`, `source_records`, `earned`, `not_yet_earned`,
`validation_debt`, `epistemic_ceiling`, `counterexamples`, `assumptions`,
`replayability`, `revision_provenance`, `limitations`, and `nonclaims`.
Unknown fields fail closed.

`source_records` binds repository-relative paths to full Git commit SHAs. The
validator resolves the commit and exact path from Git objects, rejects missing
or symlinked sources, and requires an `earned` item to reference at least one
resolved Human Final record containing an accepted decision. Each Earned entry
also carries exact source text that must occur in its referenced record, so an
unrelated accepted record cannot be reused as support for a different claim.
This is linkage, not a new source of truth: protection and authority of the
referenced Human Final remain outside PSM.

## State boundaries

- `earned` records only bounded states already accepted in source records.
- `not_yet_earned` records explicit absence without converting it to `FAIL`.
- `validation_debt.blocked_claims` identifies stronger states that remain
  unavailable. Debt removal grants nothing. NotYetEarned debt references make
  silent deletion invalid, but closure still requires an authoritative source.
- `epistemic_ceiling` preserves a source record's ceiling verbatim and cannot
  override or strengthen it.
- remediated counterexamples preserve the ordered history `FAIL`,
  `REMEDIATION`, `PASS`; collapsing that history is invalid.
- assumptions use the closed states `UNKNOWN`, `VERIFIED`, and `DISCHARGED`.
  `UNKNOWN` is never `PASS`.
- replayability is separate from independent reproduction, and v0 requires
  `independent_reproduction: NOT_CLAIMED`.

Validation returns only `VALID` or `INVALID`. `VALID` means the metadata and
declared links satisfy this closed profile. It does not approve the portfolio,
promote a claim, infer Human Final, authorize production, or discharge debt.

## Validation

```powershell
python docs/portfolio_state/validate_psm_v0.py docs/portfolio_state/portfolio_state_v0.example.json --repository .
python -m unittest docs.portfolio_state.test_validate_psm_v0 docs.portfolio_state.test_mutations -v
```

The JSON Schema documents structural constraints. The Python validator also
enforces cross-reference, Git-object resolution, contradiction, history, and
authority-boundary rules without third-party dependencies or network access.

## Nonclaims

PSM-v0 does not establish truth, correctness, safety, completeness, Human
Final, witness status, independent reproduction, evidence strength, authority,
merge permission, or production permission. It does not replace Human Final,
scope closure records, Git history, WACP, SEIC, or ECP. It does not prove that
all validation debt, assumptions, limitations, or counterexamples are known.
EvidenceStrength increase does not imply AuthorityStatus increase.
