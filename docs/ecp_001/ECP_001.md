# ECP-001 — Generic External Checkpoint Interface v0

ECP-v0 is a provider-neutral, local verification interface for detecting local
rollback, truncation, or rewrite relative to exact checkpoint bytes retained
outside the local history. It is verifier infrastructure under `tools/ecp`;
it is not a service, storage system, provider registry, or network client.

## Checkpoint

Canonical checkpoint bytes are UTF-8 JSON with sorted keys, compact separators,
and one LF at EOF. The exact v0 fields are:

- `schema_version`: `ecp.checkpoint.v0`
- `subject_log_id`: non-empty descriptive string
- `checkpoint_sequence`: non-negative integer
- `committed_head_digest`: SHA-256 digest object
- `holder_id` and `holder_basis`: non-empty descriptive strings
- `verification_method`: `retained_checkpoint_bytes.v0`
- `provider_receipt_digest`: `null` or a SHA-256 digest object
- `limitations` and `nonclaims`: lists of unique non-empty strings

Digest objects contain exactly `algorithm: sha256` and a 64-character lowercase
hex `value`. SHA-256 is ordinary byte integrity here; ECP adds no digest domain.
Holder fields and provider receipt digests are descriptive and create no trust,
independence, admission, authority, voting, quorum, or consensus.

## Verification

`verify_checkpoint` requires the local checkpoint record and exact externally
retained bytes. The retained bytes must be canonical and exactly equal the
record. Provider acquisition happens outside ECP. Local data without retained
external bytes returns `EXTERNAL_MATERIAL_MISSING`.

For an equal local sequence, the current head is compared. For a later local
sequence, the embedding system supplies a local lookup for the head digest at
the checkpoint sequence. A missing or failed lookup is
`UNVERIFIABLE_LOCAL_STATE`.

```python
from tools.ecp import canonical_checkpoint_bytes, verify_checkpoint

retained = canonical_checkpoint_bytes(checkpoint)  # externally obtained in real use
result = verify_checkpoint(
    checkpoint,
    retained,
    subject_log_id="audit-main",
    current_sequence=150,
    current_head_digest={"algorithm": "sha256", "value": current_head},
    head_digest_at_sequence=lambda sequence: {
        "algorithm": "sha256",
        "value": local_history[sequence],
    },
)
```

The closed result set is `CHECKPOINT_MATCH_CURRENT`,
`CHECKPOINT_MATCH_STALE`, `LOCAL_HISTORY_BEHIND_CHECKPOINT`,
`LINEAGE_MISMATCH`, `EXTERNAL_MATERIAL_MISSING`,
`UNVERIFIABLE_LOCAL_STATE`, `UNSUPPORTED_VERIFICATION_METHOD`, and
`INVALID_CHECKPOINT`.

## Boundaries

A match means only that the supplied local lineage is consistent with the
externally retained checkpoint. ECP establishes no truth, correctness, safety,
authority, evidence promotion, trusted time, freshness, Human Final, merge or
production permission. A stale match remains stale. Provider timestamps are
outside the schema and cannot strengthen a result. Multiple checkpoints are
verified independently and never aggregated.

Remaining limitations: external acquisition and holder authenticity are out of
scope; local history lookup correctness is an embedding-system assumption;
provider receipt absence remains `null`; holder failure and revocation are not
modeled; ECP does not prove checkpoint completeness, currentness, or external
retention quality.
