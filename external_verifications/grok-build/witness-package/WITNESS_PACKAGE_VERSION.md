## Canonical package identity model

The **annotated package tag** is the canonical package entry identity for a fixed release.

Canonical execution against an immutable tagged package:

1. Uses the exact annotated package tag for the declared `package_version`
2. Fresh-clones Weaver Forge and fetches tags from `origin`
3. Resolves `refs/tags/<tag>^{commit}` to one full 40-character peeled commit
4. Checks out that commit **detached**
5. Requires checked-out `HEAD` to equal the resolved peeled commit
6. Requires the package clone to be clean
7. Records requested tag, annotated tag object ID where required, resolved peeled commit, HEAD, detached state, and clean state in Witness evidence
8. Uses that resolved full peeled commit as the **run-specific** immutable Weaver Forge package identity

**Tag availability** is verified only through Git resolution of the annotated tag. Canonical execution requires that resolution to succeed. If resolution fails, canonical execution must stop with truthful failure evidence. After publication, the tag is immutable and its resolved full peeled commit is the package identity for that run.

The tagged package **does not embed its own commit hash**. Embedding a self-commit would create a circular identity: editing the tree to insert the commit hash changes the commit hash.

Do **not** use floating `main` as package identity. Current `main` carries next-candidate RC7 identity constants/templates only and is **not** authorized for Independent Witness handoff until an immutable tagged candidate is published and separately authorized.
